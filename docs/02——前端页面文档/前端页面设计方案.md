  - 中部：大金额输入框 + 快捷面额块（¥10 ¥20 ¥50 ¥100 ¥500）
  - 下部：分类九宫格图标（餐饮/交通/购物/娱乐/住房/医疗/教育/工资/理财/其他）
  - 底部：日期选择 + 备注 input
  - **金额校验**：`> 0`、最多两位小数（与后端 `decimal(10,2)` 一致）

  - 点击导出 → 弹窗选条件 → POST /export/excel

    - `status===4`（已过期）→ `ElMessage.warning('文件已过期，请重新导出')`，终止轮询
  - `status===2` 后触发 GET /export/download/{taskId} 用 `<a href download>` 下载
  - 返回"同步完成" → responseType blob 直接下载

## 4. 核心交互规则（必写）

### 4.1 Token 存储策略

| Token | 存储位置 | 说明 |
|---|---|---|
| accessToken | **Pinia 内存（不持久化）** | 防 XSS 持久窃取；页面刷新后通过 refresh 重新获取 |
| refreshToken | **后端 HttpOnly Cookie** | 前端不读写；Axios `withCredentials: true` 自动携带 |

> **「记住我」语义**（§3.1 登录表单）：勾选 → 后端设置 refreshToken Cookie 时带 `Max-Age=7天`（跨浏览器重启保持登录）；不勾选 → session Cookie（关闭浏览器即过期）。两种情况下 refreshToken JWT 内部均限 7 天有效，语义自洽。

### 4.2 Axios 拦截器（utils/request.ts）

**请求拦截器：**
- 若 Pinia.user.accessToken 存在 → `config.headers.Authorization = Bearer ${accessToken}`
- `config.withCredentials = true`（携带 HttpOnly Cookie）

**响应拦截器：**
- 正常 2xx + `Result.code === 200` → `return Promise.resolve(data.data)`
- `code === 2002`（乐观锁冲突）→ `ElMessage.error('该账目已被其他操作修改，请刷新页面重试')` → reject
- `code === 500/2001/其他业务错误` → `ElMessage.error(data.msg)` → reject
- **HTTP 401 或 `code === 401`**（无感刷新）：
  1. 若已有 refresh 请求在飞 → 当前失败请求塞进 pending 队列，返回新 Promise
  2. 若无锁 → 加锁 → `POST /api/auth/refresh`（带 Cookie，不需 body）
     - 成功 → 更新 Pinia accessToken → 重放 pending 队列所有请求（用新 token）
     - 失败 → 清空 Pinia → `ElMessage.warning('登录已过期，请重新登录')` → `router.push('/login?redirect=' + 当前path)` → 队列全部 reject
  3. 解锁

**下载类接口特殊处理：**
- `responseType: 'blob'` 的请求 → 不进 code 拦截器，返回响应对象本身
- `parseFilenameFromDisposition(header)` 解析 `filename*=utf-8''...` 中文文件名

### 4.3 路由守卫（router/guards.ts）

```
beforeEach(to, from, next):
  1. whiteList = ['/login', '/404']，命中 → next()
  2. Pinia.user.accessToken 存在 → 已登录访问 /login 则 next('/dashboard')，其他 next()
  3. accessToken 不存在（刷新/首次）→ 调 authApi.refreshToken()
     - 成功 → 写入 Pinia → next(to.path)
     - 失败 → next('/login?redirect=' + encodeURIComponent(to.fullPath))
  4. 登录成功后从 redirect query 取值跳转
```

### 4.4 跨月修改二次确认

- 编辑模式下，保存前对比 `原 accountDate.month` 与 `新 accountDate.month`（跨年也算）
- 不同 → `ElMessageBox.confirm('跨月修改将重置本月及上月的预算进度缓存与仪表盘缓存，是否继续？', '提示', {type:'warning'})` → 确认才 PUT /update

### 4.5 修改密码（新增功能，依赖后端补接口）

- 入口：顶栏头像下拉 → 「修改密码」→ ModifyPasswordDialog
- 表单字段：旧密码 / 新密码 / 确认新密码（新密码强度复用注册规则：6-100 位）
- 提交：`PUT /api/user/password`，body `{ oldPassword, newPassword }`（后端校验旧密码，失败返回错误码 1006）
- 成功后后端 `token_version` 自增 → 所有旧 Token（含当前会话）失效
- 前端收到成功后：清空 Pinia user store → `ElMessage.success('密码已修改，请重新登录')` → `router.push('/login')`
- **跨端依赖**：该接口后端目前不存在，需后端在 HLD/详细设计中补 U-XX 并实现，否则无法联调（见 §8 风险表）

### 6.7 导出模块

| 接口 | 方法 | 路径 | 请求体 | 响应体 |
|---|---|---|---|---|

## 8. 风险与假设

| 项 | 内容 | 建议 |
|---|---|---|
| CORS/HttpOnly Cookie | 开发环境前端 5173、后端 8080，refreshToken 需 Set-Cookie | 强制开发走 `server.proxy /api`；后端 CorsConfig 开发配置 `allowed-origin-patterns: http://localhost:5173` + `allow-credentials: true` |
| 分类字典一致性 | 后端 category 是纯 String，前端字典名必须与历史数据一致 | `types/business.ts` 字典与接口测试文档 §2.5 A-01 测试数据保持一致 |
| 401 双重处理 | 后端 401 可能既走 Result.code=401 又走真实 HTTP 401 | `utils/request.ts` 写独立 `handleUnauthorized()`，两处都调用；保证不触发二次 refresh 死循环 |
| 明暗切换仅预留钩子 | 仅引入 dark/css-vars.css + isDark store + config-provider class | 不提前写死 `--el-color-primary`，让 UI/UX 智能体后续填充 |
| 下载中文文件名 | Content-Disposition: `filename*=utf-8''%E8%B4%A6...` | `utils/auth.ts` 提供 `parseFilenameFromDisposition(header)` 用 decodeURIComponent + RFC 5987 正则解析 |

### 12.6 Nginx 路由配置

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 介绍页（首页）
    location / {
        root /usr/share/nginx/html/landing;
        try_files $uri $uri/ /index.html;
    }

    # Vue 应用
    location /app {
        alias /usr/share/nginx/html/app;
        try_files $uri $uri/ /app/index.html;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # SSE 超时配置（AI 聊天流式响应）
        proxy_read_timeout 120s;
        proxy_buffering off;
    }

    # Prometheus 指标
    location /actuator/ {
        proxy_pass http://backend:8080;
    }
}
```

### 12.11 被舍弃的方案

| 方案 | 舍弃理由 |
|---|---|
| 用 Vue 3 + Element Plus 重写介绍页 | 玻璃拟态 / 自定义动画在 Element Plus 体系内难以还原 |
| 介绍页放在 `/about` 路由 | 用户不会主动发现 `/about`，介绍页应作为首页 |
| 完全独立域名 `app.xxx.com` | 需要两个域名，个人项目不必要 |
| 场景展示板块（参考 sui.com 校园→职场） | 个人记账 + 开源项目，非 SaaS 拉新，场景展示偏营销 |
| 纯渐变色块 Hero（不放图片） | 仪表盘预览图更直观展示产品 |
| 代码片段 Hero | 偏开发者受众，普通用户无感知 |
