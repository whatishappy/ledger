### 设计说明

**为什么用 `ObjectProvider` 而非 `@Autowired(required=false)` 或 `@Lazy`？**
- `ObjectProvider` 是 Spring 原生的延迟解析容器，构造期只注入 Provider 本身（永远非 null），运行时 `getIfAvailable()` 才解析目标 Bean。
- 保留 `@RequiredArgsConstructor` 的 Lombok 风格不变，改动最小（仅字段类型 + 解析点）。
- 比 `@Autowired(required=false)` 更显式，比 `@Lazy` 更符合"配置缺失则降级"的语义。

**6011 与 6007 的区别？**
- 6011（新增）：AI Key 完全未配置，Bean 不存在，属环境配置问题。
- 6007（README 已有但 ResultCode.java 未实现，属历史文档漂移）：主备模型均不可用，属运行时故障。
- 两者语义不同，6011 应直接返回，6007 走降级重试。

### 根因重新定位
此前将降级失效归因于 `AiChatServiceImpl` 构造强注入（ObjectProvider 修复），判断不完整。真正导致 `embeddingConfig` 启动失败的是：

### 教训
`@Value("${VAR}")` 无默认值时，环境变量缺失会直接让 Bean 创建失败，与"降级返回 null"的设计意图相悖。降级模式必须同时满足两个条件：① `@Bean` 方法判空返回 null；② 上游 `@Value` 占位符有默认空值。二者缺一不可。
