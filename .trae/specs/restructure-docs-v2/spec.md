# 文档体系重构到 V2.0 Spec

## Why
项目已从 V1.5（基础记账功能）演进到 V2.0（新增 AI 模块、ezbookkeeping 功能增强、介绍页），但现有 8 份文档版本不一致：概要设计仍为 V1.5（写「预留 AI 接口」）、实施计划只覆盖 M1-M10、接口测试文档只有 16 个 V1.5 接口、详细设计为 V1.4。文档层次关系不清晰，交叉引用路径错误，内容重叠严重。需要统一升级到 V2.0，以「完整需求分析 V2.0」为主文档，建立清晰的文档层次体系。

## What Changes
- 概要设计 V1.5 → V2.0：更新功能全景图、技术栈、数据库设计、缓存策略、接口设计、部署架构、里程碑，纳入所有 V2.0 新功能
- 详细设计 V1.4 → V2.0：新增 V2.0 模块的详细设计（标签、模板、日历、导入、AI、介绍页），更新 ER 图和数据字典
- 实施计划：保留 V1.5 已完成的 M1-M10，新增 V2.0 里程碑 M11+（标签、模板、日历、导入、AI、介绍页）
- 接口测试文档：保留 V1.5 已通过的测试用例，新增 V2.0 接口的测试用例
- 完整需求分析 V2.0：修复交叉引用路径，作为主文档与其他文档建立引用关系
- 前端页面设计方案：版本号升级到 V2.0（已有第 12 章介绍页）
- 文档层次关系图：新建一张文档层次关系图，明确各文档定位和引用关系

## Impact
- Affected specs: 全部 8 份文档
- Affected code: 无代码变更，仅文档变更

## ADDED Requirements
### Requirement: 文档层次体系
系统 SHALL 建立以下文档层次关系，以完整需求分析 V2.0 为唯一主文档：
1. 完整需求分析 V2.0（主文档）— 全量需求基线
2. 概要设计 V2.0（HLD）— 架构概览，从属于完整需求分析
3. 详细设计 V2.0（LLD）— 详细实现设计，从属于概要设计
4. AI 模块需求分析 V1.0 — 模块级详细需求，被完整需求分析引用
5. 前端页面设计方案 V2.0 — 前端设计，被完整需求分析引用
6. 实施计划 V2.0 — 执行计划，从属于完整需求分析
7. 接口测试文档 V2.0 — 测试文档，从属于实施计划
8. 前端介绍页提示词 — 参考素材，非设计文档

#### Scenario: 文档版本一致性
- WHEN 开发者查阅任一文档
- THEN 该文档版本号为 V2.0（AI 模块为 V1.0 模块级文档），且引用的其他文档版本号正确

#### Scenario: 交叉引用正确
- WHEN 完整需求分析引用 AI 模块需求分析第 6 章
- THEN 引用路径为 `docs/个人记账本——AI模块需求分析.md` 而非根目录

### Requirement: 概要设计升级到 V2.0
概要设计 SHALL 从 V1.5 升级到 V2.0，纳入以下变更：
- 功能全景图：移除「AI 扩展(预留)」，改为「AI 智能助手」；新增标签、模板、日历、导入、介绍页
- 技术栈：新增 Milvus、MinIO、LangChain4j、百炼 DashScope、智谱 GLM-4、Vue 3、Tailwind CSS
- 数据库设计：新增 tag、account_tag、transaction_template、transaction_image、scheduled_transaction、ai_chat_session、ai_chat_message、ai_report_task、ai_knowledge_document 表
- 缓存策略：新增 tags、templates、ai:chat、ai:quota 缓存 Key
- 接口设计：新增标签、模板、导入、图片、定时交易、统计、用户头像、AI 模块接口
- 部署架构：新增 Milvus + etcd + MinIO 容器，Nginx 路由分离介绍页和 Vue 应用
- 里程碑：新增 P0/P1/P2 三阶段路线图

#### Scenario: 概要设计反映 V2.0 功能
- WHEN 开发者查阅概要设计功能全景图
- THEN 可见 AI 智能助手（7 个场景）、交易标签、交易模板、日历热力图、账单导入等 V2.0 新功能

### Requirement: 实施计划新增 V2.0 里程碑
实施计划 SHALL 保留 V1.5 已完成的 M1-M10 里程碑，新增以下 V2.0 里程碑：
- M11: 标签模块（tag/account_tag 表 + CRUD + 前端选择器）
- M12: 交易模板模块（transaction_template 表 + CRUD + 前端）
- M13: 交易日历热力图（统计接口 + 前端日历组件）
- M14: 支付宝/微信账单导入（解析器 + 导入接口 + 前端上传）
- M15: 用户增强（头像上传 + 登录限流 + 自动保存草稿）
- M16: AI 模块（LangChain4j + AiService + AiTools + SSE + 全部 7 场景）
- M17: 介绍页（独立静态 HTML + Tailwind + 6 板块）
- M18: 全链路联调 + Docker 部署 V2.0

#### Scenario: 实施计划覆盖 V2.0
- WHEN 开发者查阅实施计划
- THEN 可见 M1-M10（V1.5 已完成）和 M11-M18（V2.0 待实施）的完整里程碑列表

### Requirement: 接口测试文档新增 V2.0 测试用例
接口测试文档 SHALL 保留 V1.5 已通过的 56 条测试用例，新增以下 V2.0 接口测试用例：
- 标签模块：TC-T01~T04（列表/新增/修改/删除）
- 交易模板模块：TC-TP01~TP04
- 账单导入模块：TC-IM01~IM03（预览/确认导入/去重验证）
- 日历统计：TC-CA01~CA02
- AI 模块：TC-AI01~AI05（聊天/上传/会话列表/配额/降级）

#### Scenario: 测试文档覆盖 V2.0 接口
- WHEN 测试人员查阅接口测试文档
- THEN 可见 V1.5 的 56 条已通过用例和 V2.0 的新增用例
