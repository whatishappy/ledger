## 一、Summary（计划摘要）

本项目为 Spring Boot 3.5.16 单体应用，实现个人云端记账本。包含 **8 个模块**（公共、安全、用户、账目、预算、统计、导出、监控）、**4 张数据表**、**16 个 REST 接口**。

**核心技术方案**：
- 鉴权：JWT 双 Token（Access 2h + Refresh 7d HttpOnly Cookie）+ 用户版本号（替代黑名单）
- 持久层：MyBatis-Plus（乐观锁 `@Version` + 逻辑删除 `@TableLogic` + 分页）
- 缓存：Redisson，5 类缓存 Key（§13），事务提交后精确删除（`@TransactionalEventListener(AFTER_COMMIT)`）
- 幂等：服务端基于业务字段 MD5 生成 Key，5 分钟过期
- 导出：EasyExcel，同步（≤1万行）/ 异步（>1万行），任务持久化 + 分布式锁 + 启动恢复
- 监控：Micrometer + Prometheus + Grafana，7 个业务指标
- 部署：Docker Compose（app + prometheus + grafana），目标 VM `192.168.10.101`

### 里程碑 M2：安全模块（§3）

**目标**：JWT 双 Token + 用户版本号机制可用，ThreadLocal 正确管理。

#### M2.1 JWT 工具（按 §3.2 §3.3 §3.4）
- `JwtUtils.java`：
  - `generateAccessToken(userId, username, tokenVersion)` → Access Token（2h）
  - `generateRefreshToken(userId, tokenVersion)` → Refresh Token（7d）
  - `parseToken(token)` → Claims
  - `validateToken(token)` → Boolean
  - `extractUserId(token)` / `extractTokenVersion(token)`
  - Claims 含：userId（主体）、username、tokenVersion、签发时间、过期时间

#### M2.2 Token 版本号服务（按 §3.4）
- `TokenVersionService.java` + `TokenVersionServiceImpl.java`：
  - `getTokenVersion(userId)` → 从 DB/缓存读取最新版本号
  - `incrementTokenVersion(userId)` → 改密/注销时自增
  - 缓存 Key：`token:version:{userId}`，过期 7 天（§13）

#### M2.3 JWT 认证过滤器（按 §3.6）
- `JwtAuthenticationFilter.java`：
  - 解析 Authorization Bearer Token
  - 校验签名 + 有效期
  - **比对 Token 中版本号与当前版本号**（不一致 → 1004 错误码）
  - 设置 `UserContext.setUserId(userId)`
  - **finally 块强制 `UserContext.clear()`**

#### M2.4 Security 配置（按 §3.5）
- `SecurityConfig.java`：
  - 禁用 CSRF（无状态 API）
  - 启用 CORS
  - 会话策略 STATELESS
  - 放行：`/api/user/register`、`/api/user/login`、`/api/auth/refresh`、`/doc.html`、`/swagger-ui/**`、`/actuator/**`
  - 其余需认证
  - 注册 `JwtAuthenticationFilter`（在 `UsernamePasswordAuthenticationFilter` 之前）
  - BCryptPasswordEncoder（强度系数 10）

**验收**：登录返回 Access Token；携带 Token 可访问受保护接口；版本号不匹配返回 1004；ThreadLocal 无泄漏。

### 里程碑 M3：用户模块（§4 §11 U-01~U-06）

**目标**：6 个用户接口可用，注册/登录/注销全流程闭环。

- `IUserService.java` + `UserServiceImpl.java`
- `AuthController.java` + `UserController.java`：
  - POST `/api/user/register`（U-01，§4.3）：用户名唯一校验 → BCrypt 加密 → 默认昵称=username → status=1 → token_version=1
  - POST `/api/user/login`（U-02，§4.4）：BCrypt 比对 → 读取 token_version → 生成双 Token → Refresh 写 HttpOnly Cookie

  - POST `/api/auth/refresh`（U-05，§3.5）：验证 Refresh Token → 版本号校验 → 签发新 Access Token
  - GET `/api/user/info`（U-04）：返回当前用户基本信息
  - DELETE `/api/user/delete`（U-06，§4.5）：验证密码 → 用户名脱敏 `user_del_{timestamp}` → 昵称改"已注销用户" → status=0 → token_version+1 → 清缓存 → 异步清理导出文件

#### M3.3 DTO
- `RegisterRequest`（username 3-50 位字母数字下划线，password 6-100 位）
- `LoginRequest`、`LoginVO`（accessToken）、`UserInfoVO`

**验收**：注册→登录→获取信息→刷新 Token→注销全流程通过；注销后旧 Token 返回 1004；登录失败统一 1002（防撞库）。

### 里程碑 M4：账目模块（§5 §11 A-01~A-04）

**目标**：4 个账目接口可用，幂等 + 跨月双清 + 乐观锁全部落地。

#### M4.1 账目实体与 Mapper（按 §10.2.2）
- `Account.java`：`@TableName("account_book")`、`@Version`、`@TableLogic`
- `AccountMapper.java`：继承 `BaseMapper<Account>` + 5 个聚合 SQL（供 M5/M6/M7 复用）：
  - `sumAmountByTypeAndDateRange(userId, type, start, end)` → 月度收入/支出汇总
  - `sumExpenseGroupByCategory(userId, start, end)` → 支出分类占比
  - `sumAmountGroupByDate(userId, start, end)` → 按日汇总（趋势）
  - `sumSpentGroupByCategory(userId, start, end)` → 预算消费汇总（N+1 优化关键）
  - `countByConditions(userId, type, category, start, end)` → 导出数据量统计

#### M4.2 账目服务与 4 个接口（按 §5.3~§5.6 §11）
- `IAccountService.java` + `AccountServiceImpl.java`
- `AccountController.java`：
  - POST `/api/account/add`（A-01，§5.3）：
    - 金额 > 0、分类枚举校验、业务日期 ≤ 当前+7天
    - **幂等**：服务端 MD5(userId+category+amount+accountDate) → 查 Redis → 命中返回已有 ID → 未命中则入库 → 写 Redis（5 分钟）
    - 发布 `AccountChangeEvent`（userId, month）
  - POST `/api/account/page`（A-02，§5.4）：
    - 强制拼接 user_id（数据隔离）
    - 按 account_date 倒序、create_time 倒序
    - 可选筛选：type/category/startDate/endDate/keyword(remark 模糊)
  - PUT `/api/account/update`（A-03，§5.5）：
    - 校验账目归属（user_id 匹配）
    - 乐观锁（version 字段，影响行数 0 → 2002）
    - **跨月双清**：旧月份 ≠ 新月份 → 发布两个事件（旧月、新月）
  - DELETE `/api/account/delete/{id}`（A-04，§5.6）：
    - 逻辑删除（is_deleted=1）
    - 校验归属 → 发布事件（该月）

#### M4.3 事件驱动缓存清除（按 §5.3 §13）
- `AccountChangeEvent.java`：userId、month
- `AccountChangeListener.java`：`@TransactionalEventListener(AFTER_COMMIT)`
  - 删除 `dashboard:{userId}:{month}` + `budget:{userId}:{month}`

**验收**：幂等重复提交返回同一 ID；跨月修改触发双清；并发修改返回 2002；删除后查询自动过滤。

**目标**：2 个预算接口可用，N+1 已优化，进度实时计算。

> **M5 先于 M6**：M6 仪表盘步骤 11 需调用预算模块。

### 里程碑 M6：统计模块（§7 §11 S-01）

**目标**：仪表盘接口可用，缓存命中率可观测，Redis 降级可用。

#### M6.1 统计服务与接口（按 §7.3 §11）
- `IDashboardService.java` + `DashboardServiceImpl.java`
- `StatisticsController.java`：GET `/api/statistics/dashboard?month=YYYY-MM`（S-01）
- VO：`DashboardVO`、`CategoryStatVO`、`TrendVO`

#### M6.2 仪表盘 14 步流程（按 §7.3 步骤 1-14）
1. 获取 userId
2. 校验月份格式（默认当前月）
3. 查 Redis 缓存，命中直接返回
4. 计算月度起止日期
5. 查月度收入（type=1，复用 `sumAmountByTypeAndDateRange`）
6. 查月度支出（type=0）
7. 结余 = 收入 - 支出
8. 查支出分类占比（GROUP BY category，复用 `sumExpenseGroupByCategory`）
9. 计算每个分类百分比
10. 查近 7 日每日收支（GROUP BY DATE，复用 `sumAmountGroupByDate`，按日补全无数据日期）
11. **调用 `IBudgetService.listBudgetsWithProgress(month)` 获取预算进度**（M5 已实现）
12. 组装 DashboardVO
13. 写 Redis 缓存（5 分钟）
14. 返回

#### M6.3 缓存降级
- CacheService 已 try-catch 包裹，Redis 异常返回 null → 触发 DB 查询，接口仍可用

**验收**：二次访问 dashboard ≤ 50ms；改账目后缓存清除；Redis 断开接口仍可用。

### 里程碑 M7：导出模块（§8 §11 E-01~E-03）

**目标**：3 个导出接口可用，大文件异步生成可下载，任务可恢复。

#### M7.1 导出实体与 Mapper（按 §10.2.4）
- `ExportTask.java`：`@TableName("export_task")`
- `ExportTaskMapper.java`：继承 `BaseMapper<ExportTask>`

#### M7.2 导出服务与 3 个接口（按 §8.3 §11）
- `IExportService.java` + `ExportServiceImpl.java`
- `ExportController.java`：
  - POST `/api/export/excel`（E-01，§8.3）：
    - 单用户限流：5 分钟 1 次（Redis 计数器）
    - 复用 `countByConditions` 统计数据量
    - ≤ 10000 行：同步分页查询 → EasyExcel 写 `ByteArrayOutputStream` → 返回文件流
    - \> 10000 行：创建任务记录（status=0）→ 提交异步线程池 → 返回 taskId
    - \> 100 万行 → 4001
  - GET `/api/export/status/{taskId}`（E-02）：返回任务状态 + 下载链接
  - GET `/api/export/download/{taskId}`（E-03）：校验归属 → 返回文件流

#### M7.3 异步导出执行器（按 §8.3 步骤 6-8）
- `ExportTaskExecutor.java`：
  - 线程池：core=2, max=5, queue=100（`ExportThreadPoolConfig`）
  - 分布式锁：`RLock("export:lock:{taskId}")`，tryLock(10s, 30min)
  - 全局并发上限 5：`Semaphore(5)`
  - 分页查询（pageSize=5000）+ EasyExcel 写本地文件
  - 完成后更新 status=2、file_url、file_size、row_count
  - 失败更新 status=3 + error_msg
  - 埋点：成功/失败计数

#### M7.4 任务状态机与恢复（按 §10.2.4）
- 状态机：待处理(0) → 处理中(1) → 已完成(2) → 已过期(4)；失败(3) → 已过期(4)
- `ExportTaskRecoveryRunner.java`：实现 `ApplicationRunner`
  - 启动时扫描 `status=1 且 update_time < NOW() - INTERVAL 30 MINUTE`
  - 重置为待处理(0)，重新入队

#### M7.5 文件清理（按 §10.5）
- `ExportFileCleanupTask.java`：`@Scheduled(cron = "0 0 3 * * ?")`
  - 标记过期：`UPDATE export_task SET status=4 WHERE expire_time < NOW()`
  - 删除 7 天前记录 + 删除对应文件

#### M7.6 配置
- `ExportProperties.java`：file-path、sync-threshold(10000)、max-rows(1000000)、retain-days(7)

**验收**：小数据量同步下载；大数据量返回 taskId 可轮询下载；重启后未完成任务可恢复；定时清理生效。

## 五、Risk & Mitigation（风险与应对）

| 风险 | 应对措施 |
| :--- | :--- |
| 跨月缓存未双清 | 代码 Review 强制检查；`AccountChangeListener` 处理双月份事件 |

| 数据越权 | 所有业务操作强制带 user_id 条件校验 |
| Redis 不可用 | CacheService try-catch 降级直查 DB |
